La démo lance Rocket Auth avec des données prêtes à l'emploi :

- des comptes locaux et LDAP (annuaire OpenLDAP), avec le groupe `rocket-admins` pour les administrateurs ;
- trois **clients OAuth** de confiance, les briques de la suite : **Rocket Mailer** (port 3000), **Rocket Cloud** (port 3200) et **Rocket Print** (port 3300), avec des secrets connus ;
- une application externe, avec un jeton connu, qui peut agir au nom des utilisateurs.

::tabs
  :::tabs-item{label="En local" icon="i-lucide-laptop"}
  ```bash [Terminal]
  docker compose -f compose.yaml -f compose.demo.yaml up -d --build
  ```

  Puis ouvrez http://localhost:3100 (Rocket Auth) et http://localhost:3101 (cette documentation et le changelog).
  :::

  :::tabs-item{label="GitHub Codespaces" icon="i-simple-icons-github"}
  1. Sur GitHub : **Code → Codespaces → Create codespace**.
  2. Attendez la fin de la commande de démarrage (quelques minutes la première fois).
  3. Ouvrez le port 3100 (Rocket Auth) depuis l'onglet **Ports**.
  :::
::

## Comptes

| Compte | Mot de passe | Type |
|---|---|---|
| `admin@example.org` | `demo-admin-password` | local, administrateur, groupe `rocket-admins` |
| `alice@example.org` | `demo-alice-password` | local |
| `marie.martin@example.org` | `password` | LDAP, administratrice par son groupe `rocket-admins` |
| `jean.dupont@example.org` | `password` | LDAP |

## Clients OAuth

| Client ID | Application | Secret | Adresse de retour |
|---|---|---|---|
| `rocket-mailer` | Rocket Mailer | `demo-rocket-mailer-client-secret` | `http://localhost:3000/auth/callback` |
| `rocket-cloud` | Rocket Cloud | `demo-rocket-cloud-client-secret` | `http://localhost:3200/auth/callback` |
| `rocket-print` | Rocket Print | `demo-rocket-print-client-secret` | `http://localhost:3300/auth/callback` |

Ils sont déclarés par la variable `DEMO_OAUTH_CLIENTS` de `compose.demo.yaml`, une entrée par application, séparées par `;` :

```text
clientId|Nom|secret|adresse de retour|adresse après déconnexion|adresse de l'application|icône
```

L'adresse de l'application et l'icône placent l'application dans le sélecteur de la suite.

## Scénarios

1. **Administration.** Connectez-vous avec `admin@example.org` et ouvrez **Administration → Clients OAuth** : l'émetteur à configurer dans les applications s'affiche en haut de la page. Modifiez un client, régénérez son secret, désactivez-le.
2. **Découverte.** Le document que lisent les applications :
   ```bash [Terminal]
   curl http://localhost:8100/.well-known/openid-configuration
   curl http://localhost:8100/oauth/jwks
   ```
3. **Sélecteur d'applications.** Ce que les briques en mode suite affichent dans leur menu :
   ```bash [Terminal]
   curl http://localhost:3100/api/suite/apps
   ```
   Désactivez un client, ou videz son adresse : il disparaît de la liste. Les briques la gardent en cache 5 minutes.
4. **Brancher une brique.** Lancez par exemple Rocket Print en mode suite, avec `ROCKET_AUTH_URL=http://localhost:8100`, `ROCKET_AUTH_CLIENT_SECRET=demo-rocket-print-client-secret` et, si son API tourne dans un conteneur, `ROCKET_AUTH_INTERNAL_URL` : l'adresse de Rocket Auth vue depuis ce conteneur (voir [Brancher la suite Rocket](/administration/suite)). Sa page de connexion renvoie vers Rocket Auth ; `admin@example.org` y devient administrateur grâce au groupe `rocket-admins`.
5. **Application.** Une application agit au nom d'Alice :
   ```bash [Terminal]
   curl http://localhost:3100/api/me \
     -H "Authorization: Bearer raa_demo_rocket_auth_do_not_use_in_production" \
     -H "X-Impersonate-User: alice@example.org" -H "Accept: application/json"
   ```

::warning
Les mots de passe, les secrets des clients et le jeton de la démo sont publics : ne l'exposez pas sur Internet.
::
