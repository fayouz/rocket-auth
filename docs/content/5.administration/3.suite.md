Chaque brique Rocket fonctionne **seule** (mode autonome, par défaut) ou **dans la suite**. En mode suite :

- la connexion passe uniquement par Rocket Auth, directement depuis la page de connexion de la brique ;
- les comptes sont créés à la première connexion ; utilisateurs, groupes et annuaire se gèrent dans Rocket Auth ;
- les administrateurs de la brique sont les membres d'un groupe de Rocket Auth ;
- le menu de la brique affiche le **sélecteur des applications** de la suite et un lien **Mon compte** vers l’interface de Rocket Auth (son adresse `FRONTEND_URL`, publiée par `GET /api/suite/apps`) ;
- se déconnecter de la brique termine aussi la session Rocket Auth.

## Brancher une brique

Il faut un client dans Rocket Auth, et quelques variables dans la brique.

::steps{level="3"}

### Déclarer la brique dans Rocket Auth

Dans **Administration → Clients OAuth → Nouveau client** (voir [Clients OAuth](/administration/clients)), avec l'adresse publique de la brique, ici `https://print.exemple.com` :

| Champ | Valeur |
|---|---|
| Nom de l'application | `Rocket Print` |
| Client ID | `rocket-<id>` : `rocket-mailer`, `rocket-cloud`, `rocket-print`… C'est la valeur par défaut attendue par la brique. |
| Adresse de l'application | `https://print.exemple.com` : la brique apparaît dans le sélecteur de la suite |
| Icône | par exemple `i-lucide-mail`, `i-lucide-cloud`, `i-lucide-printer` |
| URL de retour | `https://print.exemple.com/auth/callback` |
| URL après déconnexion | `https://print.exemple.com/login?logged_out=1` |
| Scopes autorisés | `openid`, `email`, `profile`, `groups` (valeurs par défaut) |
| Flux autorisés | Code d'autorisation et jeton de rafraîchissement (valeurs par défaut) |
| Client confidentiel | Oui |
| Application de confiance | Oui : les applications de la suite ne demandent pas l'accord des utilisateurs |

Notez le **secret** affiché à la création.

### Configurer la brique

Dans l'environnement de l'API de la brique (son `compose.yaml` ou son `.env.local`) :

| Variable | Valeur | Défaut |
|---|---|---|
| `ROCKET_AUTH_URL` | L'émetteur de Rocket Auth (`OIDC_ISSUER`), par exemple `https://auth.exemple.com`. Renseignée : mode suite. | — (mode autonome) |
| `ROCKET_AUTH_INTERNAL_URL` | L'adresse de Rocket Auth vue par l'API de la brique, si elle diffère (ex. `http://auth-api` quand les deux partagent un réseau Docker) | l'adresse publique |
| `ROCKET_AUTH_CLIENT_ID` | Le client ID | `rocket-<id>` |
| `ROCKET_AUTH_CLIENT_SECRET` | Le secret du client | — |
| `ROCKET_AUTH_ADMIN_GROUP` | Le groupe de Rocket Auth dont les membres administrent la brique | `rocket-admins` |
| `ROCKET_LOCAL_LOGIN` | `1` : garde un accès de secours par mot de passe local (comptes créés avec `app:user:create`) | `0` |

Redémarrez l'API de la brique. Elle déclare d'elle-même Rocket Auth comme serveur d'authentification **géré** (en lecture seule dans son administration), à la première connexion ou avec :

```bash [Terminal]
php bin/console rocket:suite:sync
```

### Vérifier

Ouvrez la brique : sa page de connexion renvoie vers Rocket Auth, puis revient connectée. Son menu affiche les autres applications de la suite.

::

## Les administrateurs des briques

La brique demande le scope `groups` et donne le rôle administrateur aux utilisateurs dont la revendication `groups` contient `ROCKET_AUTH_ADMIN_GROUP` (`rocket-admins` par défaut) ; elle le retire aux autres, à chaque connexion.

Dans Rocket Auth, mettez donc les administrateurs de la suite dans ce groupe :

- **comptes LDAP** : un groupe de l'annuaire nommé `rocket-admins` (par exemple `cn=rocket-admins,ou=groups,dc=exemple,dc=com`), puis une synchronisation ;
- **comptes locaux** : page **Utilisateurs**, bouton **Groupes**, ajoutez `rocket-admins`.

Voir [Utilisateurs et LDAP](/administration/users-ldap#groupes). Pour des administrateurs différents par brique, donnez à chaque brique son propre `ROCKET_AUTH_ADMIN_GROUP` (par exemple `print-admins`).

::note
Le rôle administrateur **de Rocket Auth** est distinct : il vient de la configuration initiale, de la page **Utilisateurs** ou du groupe des administrateurs de l'annuaire (`LDAP_ADMIN_GROUP_DN`).
::

## Le sélecteur d'applications

Les briques en mode suite lisent la liste des applications sur `GET /api/suite/apps` de Rocket Auth (par `ROCKET_AUTH_INTERNAL_URL` si elle est renseignée) et la gardent 5 minutes en cache. Y figurent les clients **actifs** qui ont une **adresse d'application**, avec leur nom, leur icône et leur description. Voir [OpenID Connect](/api/openid-connect#applications-de-la-suite).

Pour retirer une application du sélecteur sans la débrancher, videz son adresse.

## Revenir en mode autonome

Videz `ROCKET_AUTH_URL` dans la brique et redémarrez-la : le serveur d'authentification Rocket Auth y est désactivé et rendu à ses administrateurs, et la brique gère de nouveau ses comptes.

## Autres applications

Toute application compatible OpenID Connect se branche de la même façon : un client dans Rocket Auth, puis l'émetteur, le client ID et le secret dans l'application. Voir [OpenID Connect](/api/openid-connect).
