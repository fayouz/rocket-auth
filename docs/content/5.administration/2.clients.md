Un **client OAuth** représente une application qui connecte ses utilisateurs avec Rocket Auth : une brique Rocket, un intranet, un outil du marché compatible OpenID Connect… Les clients se gèrent dans **Administration → Clients OAuth**.

En haut de la page, Rocket Auth rappelle l'**émetteur** à configurer dans les applications (`OIDC_ISSUER`) : elles y trouvent tout le reste, dans `<émetteur>/.well-known/openid-configuration`.

## Créer un client

**Nouveau client**, puis :

| Champ | Rôle |
|---|---|
| **Nom de l'application** | Affiché aux utilisateurs (page d'autorisation, applications autorisées, sélecteur de la suite) |
| **Client ID** | Identifiant public (lettres, chiffres, `.`, `_`, `-`). Vide : généré. Ne peut plus changer ensuite. Pour une brique Rocket : `rocket-<id>`, par exemple `rocket-print`. |
| **Description** | Affichée sur la page d'autorisation |
| **Adresse de l'application** | Page d'accueil de l'application. Renseignée, elle place l'application dans le **sélecteur d'applications** de la suite. |
| **Icône** | Icône du sélecteur, par exemple `i-lucide-printer` |
| **URL de retour (redirect URI)** | Une ou plusieurs adresses où Rocket Auth renvoie le code, par exemple `https://print.exemple.com/auth/callback`. Obligatoire avec le flux « code d'autorisation ». |
| **URL après déconnexion** | Adresses où l'application peut renvoyer l'utilisateur après la déconnexion (`post_logout_redirect_uri`), par exemple `https://print.exemple.com/login?logged_out=1` |
| **URL de déconnexion back-channel** | Facultative. Où Rocket Auth envoie, de serveur à serveur, un jeton de déconnexion quand l'utilisateur se déconnecte, ou que son compte est désactivé ou supprimé (`backchannel_logout_uri`), par exemple `https://print.exemple.com/api/auth/oidc/backchannel-logout`. Les briques Rocket la déclarent elles-mêmes : voir [Déconnexion back-channel](/api/openid-connect#déconnexion-back-channel). |
| **Scopes autorisés** | Ce que l'application peut demander : `openid`, `profile`, `email`, `groups` (par défaut) et `offline_access` |
| **Flux autorisés** | Code d'autorisation et jeton de rafraîchissement (par défaut), identifiants client (application seule, sans utilisateur). Les **identifiants client** permettent notamment à une brique d'appeler les autres briques de la suite avec un jeton de Rocket Auth : voir [Appels entre briques](/administration/suite#appels-entre-briques). |
| **Client confidentiel** | Application serveur, avec un secret. Sinon, client **public** (navigateur, mobile), qui doit utiliser PKCE et ne peut pas utiliser les identifiants client. Ne peut plus changer ensuite. |
| **Application de confiance** | Application interne : les utilisateurs ne voient pas la page d'autorisation |

Les adresses de retour, de déconnexion et de déconnexion back-channel sont des URL `http` ou `https` absolues, sans fragment (`#…`). Elles sont comparées **à l'identique** : déclarez chaque variante utilisée (port, chemin, paramètres).

::warning
À la création d'un client confidentiel, Rocket Auth affiche le **secret** (`ras_…`) une seule fois. Copiez-le dans la configuration de l'application : il n'est stocké que sous forme de hash et ne pourra plus être affiché.
::

## Gérer les clients

La liste montre, pour chaque client, son type (confidentiel ou public, de confiance), ses adresses de retour et sa **dernière utilisation**. Pour chaque client :

- **Actif** : un client désactivé ne peut plus connecter personne, ni obtenir ou rafraîchir de jetons, et disparaît du sélecteur de la suite ;
- **Modifier** : tout, sauf le client ID et le type, fixés à la création ;
- **Régénérer le secret** : l'ancien secret cesse immédiatement de fonctionner ; l'application doit être reconfigurée avec le nouveau ;
- **Supprimer** : les utilisateurs ne peuvent plus se connecter à cette application avec Rocket Auth.

## Application de confiance ou non

| | De confiance | Non |
|---|---|---|
| Page d'autorisation | Jamais | À la première connexion, puis quand l'application demande davantage |
| Applications autorisées (côté utilisateur) | N'apparaît pas | L'utilisateur peut retirer l'accès |
| Pour | Les briques Rocket, les applications internes | Les applications de partenaires, ou dont les utilisateurs doivent accepter le partage |

## API

Réservée aux administrateurs.

| Méthode | Chemin | Rôle |
|---|---|---|
| `GET` | `/api/oauth/clients` | Liste des clients |
| `POST` | `/api/oauth/clients` | Création ; la réponse contient `plainSecret`, une seule fois |
| `GET`, `PATCH`, `DELETE` | `/api/oauth/clients/{id}` | Lecture, modification, suppression |
| `POST` | `/api/oauth/clients/{id}/regenerate-secret` | Nouveau secret : `{ "secret": "ras_…", "secretHint": "…" }` |

Champs : `name`, `description`, `clientId`, `confidential`, `redirectUris`, `postLogoutRedirectUris`, `backchannelLogoutUri`, `allowedScopes`, `grantTypes`, `homeUrl`, `icon`, `trusted`, `enabled` ; en lecture seule `secretHint` (début du secret) et `lastUsedAt`.
